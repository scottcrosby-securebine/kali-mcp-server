# Domain documentation

This is a single-context repository.

## Before exploring

Read `CONTEXT.md` at the repository root when it exists, then read relevant architectural decisions under `docs/adr/`. If either location is absent, continue without treating the absence as an error; domain-modeling work creates those documents when real terminology or decisions are resolved.

## Vocabulary

Use terms defined in `CONTEXT.md` in issues, specifications, tests, and implementation. Do not replace established terms with synonyms. If a needed concept is absent, reconsider whether it belongs or record it as a domain-modeling gap.

## Architectural decisions

Surface conflicts with an existing ADR explicitly. Do not silently override a recorded decision.
