# Report IA rewrite (#41) — build spec

**Status: APPROVED 2026-08-28 (Scott, defaults D1-D4 accepted).** This is the anchor for row 22. #41 is a target
specification with no written section spec; this authors one from #41's 7
requirements and the primary sources, grounded in what each scanner actually
emits. Approve or redline the `[DECISION]` lines, then it drives the build.

Scope: the **combined** report (`generate_report` no-ref → `render_combined`).
The single-ref report is one scanner and is out of scope here — see D2.

## What the data supports

| Scanner family | Keys available | Remediation model |
|---|---|---|
| trivy | VulnerabilityID (CVE), PkgName, InstalledVersion, FixedVersion, Severity, CVSS, References, DataSource, + EPSS/KEV | **package upgrade** — one `pkg X→Y` clears N CVEs |
| nuclei | id (often CVE), Severity, Title, reference, remediation, + EPSS/KEV | **per-CVE** — no package; template remediation/reference |
| nikto | id (OSVDB/nikto-N), Title, Severity, evidence(url), reference, remediation(header class) | **web hardening** action |
| sslscan/testssl/sslyze | tls-proto-*/tls-cipher-*, Severity, Title, remediation | **web hardening** (TLS) action |
| whatweb / dns_recon / wafw00f / ffuf / gobuster / dirb | INFO enumerations | none — informational |

Consequence: a package-grouped queue is trivy-shaped. nuclei CVEs are CVE work
units. nikto+TLS are hardening actions. The rest is enumeration.

## Sections

Progressive disclosure uses native `<details>/<summary>` — the report stays
**scriptless** (CSP at `_REPORT_TEMPLATE`), no JS.

**S1 — Cover & provenance.** Title, target(s) in session, "as of" timestamp,
tool/feed versions (incl. EPSS/KEV feed dates or "Not enriched"), source =
captured session. Replaces the current bare title band.

**S2 — Executive band.** Counts (total findings, deduped), severity histogram,
**Actively exploited (KEV): N**, **Fixable now: N** (findings carrying a
FixedVersion or a remediation), **Top 3 upgrades by CVEs cleared**, and a
**Limitations card** that states plainly what was not collected (exposure,
reachability, asset criticality; EPSS/KEV when the feeds are absent).

**S3 — Fix-first queue.** Ordered list of remediation **work units**:
- a trivy package upgrade (`upgrade <pkg> <installed> → <fixed>, clears N CVEs`), child CVEs in a `<details>` drawer;
- a nuclei CVE remediation (single work unit, its remediation + reference);
- `[DECISION D1]` nuclei CVEs and TLS hardening: **nuclei CVE work units go in S3; nikto + TLS go in S6.** (Alternative: TLS in S3 too.)

Ordering, honestly labelled **"prioritized by available signals"** (not
"risk"): has-fix → KEV → EPSS → (max CVSS, then critical/high count) → CVEs
cleared. Ties broken by CVE id for determinism.

**S4 — Package matrix.** Table: package · installed · fixed · CVEs cleared ·
max severity. Trivy only. The S3 headlines, tabulated.

**S5 — CVE explorer.** Per-CVE drawer: CVE, installed→fixed, CVSS, EPSS, KEV,
reference, scanner, occurrence count + provenance (#26/#37: dedupe by
`{scanner,target,id,severity,evidence,reference}`, keep the count). Behind
`<details>` so the exec layer stays scannable.

**S6 — Web hardening.** nikto + TLS findings, ranked by their own severity, NOT
folded into the CVE ranking (requirement 4). Each shows title, evidence,
remediation, reference.

**S7 — Evidence appendix.** The INFO enumerations (dns, whatweb, discovered
paths, WAF). Demoted, not deleted; kept for provenance.

**S8 — Methodology & limitations.** Scanners run, feed versions + staleness,
the "signals not risk" disclaimer, and the never-imply-uncollected rule
(requirement 7): reserved fields read "Not enriched"/"Not tracked", never 0.
